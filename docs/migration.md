# 安装与迁移

## 新安装

按 [README 安装步骤](../README.md#安装)在新的 NAS 或 Linux 主机上运行。默认 `./data` 与 `./media` 都相对于 Compose 项目目录解析；新装前请确认位置，首次进入后设置管理员密钥与自己的 Cookie。源码包不是离线镜像，首次构建需要联网。

## 将现有 NAS 部署切换到独立仓库

切换前等现有下载任务结束，记录当前 Compose 项目名、服务名、配置、覆盖文件、环境变量、端口及实际挂载。`docker compose ls` 和当前部署的 `docker compose config` 可辅助核对；从容器实际挂载信息确认 `/data`、`/media`、可选 `/legacy` 的主机绝对路径。现有服务名为 `douyin-library`；保留部署使用的 Compose 项目名、服务名、端口和原有挂载，尤其保留旧库的只读方式及可选核显配置。请按实际部署核对，勿以示例替换。

停止旧服务后再备份 `.env`、Compose 配置及完整数据目录，包括 SQLite 数据库及其 WAL/SHM 文件；媒体按原有备份方式另行保存。记录旧容器使用的镜像 ID，并为其另存一个回退标签，以免新构建覆盖原镜像标签。不要删除旧镜像、卷、数据或媒体。

新仓库位置改变时，`./data`、`./media` 也会指向新位置；在新配置中将 `APP_DATA_DIR`、`APP_MEDIA_DIR` 及需要时的 `APP_LEGACY_DIR` 明确设为核对过的原主机绝对路径。旧 Compose 的相对路径、覆盖文件路径也要按新位置重新核对。运行前检查 `docker compose config` 展开的项目名、服务、端口和挂载，并确认没有两个实例同时使用同一份 SQLite 数据目录。使用原项目名（必要时通过 `docker compose -p <原项目名>` 指定）及 `douyin-library` 服务启动；不同项目名会产生另一组容器。飞牛等界面请核对其实际项目名与合并后的挂载。

启动后核对 `/health`、登录、任务和媒体库，再按需要在受控条件下检查下载；此前数据、媒体路径和权限须与旧部署一致。不要把健康接口响应当作真实下载和全部播放能力的验证。

## 回退

先停止新服务，确认没有实例继续使用数据目录。保留切换前的原配置、原源码或 Compose 文件及旧镜像标签；按原项目名和原挂载恢复旧服务，必要时先将保存的旧镜像恢复到原 Compose 使用的镜像标签，再用原配置以不重新构建的方式启动。若新版本已修改数据库而旧版本不能安全读取，需先保全切换后的数据，再按自己的恢复方案还原切换前的完整数据库备份；这可能丢失切换后产生的记录，不能声称两版本数据库必然兼容。

本文是切换方法，本次整理不会自动部署、停止服务或修改现有 `data/`、`media/`。
