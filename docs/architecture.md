# 项目结构

抖音收藏库（Cloudrift）提供下载任务、网页媒体库和浏览器助手。当前源码版本网站 1.4.5、助手 1.13.0。下载核心已随本项目源码自包含在 `vendor/TikTokDownloader/`，运行时不需要旧项目目录或另行克隆核心；首次构建仍需联网获取基础镜像、依赖、FFmpeg 和驱动。

- `app/__main__.py`、`app/main.py`：服务入口、API 和任务调度。
- `app/core.py`：调用内置下载核心，规范输入、下载目录和结果校验。
- `app/store.py`、`app/legacy.py`：配置、SQLite、浏览历史、离线评论与历史媒体的只读索引。
- `app/comments.py`、`app/comment_browser.py`、`app/comment_accounts.py`、`app/comment_assets.py`：用户主动选择的评论采集、附件与导出；评论图片保存在数据目录。
- `app/playback.py`、`app/static/`：播放兼容缓存和网站界面。
- `app/cookie_sync.py`、`userscripts/`：浏览器助手及 Cookie 同步。
- `vendor/TikTokDownloader/`：固定来源的上游下载核心及本项目适配；来源与修改见 [补丁说明](../vendor/TikTokDownloader/PATCHES.md)。
- `Dockerfile`、`docker-compose*.yml`、`tools/`：构建、部署、源码打包及 FFmpeg／可选核显运行时准备。
- `tests/`：使用合成数据的自动检查。

浏览历史只记录助手启用后识别到的浏览事件，数量补充查询使用独立未登录会话。评论只有主动保存才访问抖音，已保存数据可在局域网离线阅读；真实平台接口与长期运行仍需实测。

旧个人下载管理器仅供历史参考，没有混入本项目。原核心的说明文件和许可证随源码保留，运行数据、媒体、凭据及离线缓存不属于公开源码包。

## 评论账号分流约定

默认角色是小号 secondary。大号 primary 仅在用户本次选择“大号浏览器”或“后台大号”并点击相应按钮时授权，不持久记忆为默认；不会因失败、验证码或小号缺失切换账号。抖音关注关系与收藏库订阅是不同概念，不同步关注列表，也不据此猜账号。

大号自动复用已保存的视频下载 Cookie，通过本地 UID 与登录会话迹象派生身份；启动时迁移，保存下载 Cookie 时在同一事务协调。身份变化或不可用会暂停并中断活动评论；仅刷新同一 UID 不会解除暂停。若新大号与小号相同则清除小号绑定。旧大号浏览器绑定请求拒绝，避免覆盖下载账号基准。

小号在设置页粘贴 Cookie，通过带管理员鉴权且 no-store 的 POST `/api/comment-accounts/secondary-cookie` 临时派生 HMAC 身份后丢弃原文，不替换下载 Cookie，不把小号原文写入数据库、URL或日志；输入提交后清空，页面立即显示结果。原小号 nonce/助手派生绑定接口保留兼容。未完成两者时评论保持暂停；绑定成功不验证平台登录有效性，浏览器补抓仍须登录同一小号。角色指纹只防个人部署中的误操作，不是平台身份认证，也无法约束被管理员篡改的脚本；Cookie 的稳定性及小号绑定仍需用户实测。

每个评论任务保存所选角色与派生身份。一次性认领将浏览器会话绑定到一个页面 client_id，错身份、旧助手、其他标签及角色冲突均拒绝；后台通道须本次授权大号，且实际 Cookie 身份须匹配。旧无身份任务升级后停止，已存评论和附件保留。

平台 XHR 发出之前，助手必须取得服务端原子许可；同一派生身份跨作品、标签和重启共享预留计次。工具上限为滚动24小时200次、至少3秒间隔、每15次额外休息8–15秒；网络错误、取消或崩溃不退回已预留次数。这些仅是本工具自限，不是平台承诺的安全阈值，不统计原生页面和其他程序请求。

验证码或不明访问失败使所有评论持久暂停，不影响原媒体下载；用户在网站手动解除也不会自动重开任务。浏览器先保存本地受阻标记，再尝试上报；NAS离线时服务端无法即时获知，后续操作优先补报。已上报后允许显式绑定账号，但绑定不清除受阻标记且保持暂停；只有网站明确解除后，用户再次点击新开始才可清理本地标记。

原评论数据库统一累计，不按账号另建媒体库；同一评论ID不得在一级/其他楼层间迁移，归属冲突整页事务拒绝。状态/导出记录最近任务的角色，不能据此推断每一条历史评论的来源。普通API不显示派生身份，URL和日志不得包含原Cookie、UID或密钥。
